## 完整流程
1. Excel审核表 + ZIP音频 → 按状态/角色/时长筛选 → 校验SHA256 → 文本去重 → 跨等级选40条候选。
2. 本地复核页逐条试听 → 确认实际转写文本 → 导出JSON → 生成 verified.jsonl。
3. 原始音频保留 → FFmpeg 转16kHz/单声道/PCM16 WAV。
4. 相同录音分别进入 Whisper、SenseVoiceSmall、中文Paraformer。不给模型标准答案、不设置答案热词。
5. 保存原始转写 → 相同规范化规则计算CER → 与题目标准拼音做动态规划对齐 → 生成四类疑似偏误。
6. 有人工偏误金标才计算分类精确率/召回率/F1；无金标则为null，不能写“准确率100%”。
7. 输出每条结果、失败原因、模型配置/软件版本/音频哈希、汇总和Markdown对比。
8. 网页上传原有调用 run_diagnosis → diagnose 保持不变，通过环境变量切模型。

## 算法含义
标准逐字tokens优先，缺失时用pypinyin按词语上下文生成。计算拼音统一小写数字调、轻声5、ü/v统一。
对齐是加权Levenshtein动态规划：完全一致成本0，仅声调不同成本1，声韵母不同成本4，增漏各4。
同成本优先对角、删除、插入，结果可复现。连续增读全部保留，支持句首和句尾边界。
声韵母相同而声调不同标tone；其他替换标substitution；删除omission；插入insertion。
索引从0开始，仅计汉字，标点不计；boundary_index=0为句首，=字数为句尾。
旧输出 tokens[].err(tone/sf/del)、gap_errors(ins)继续兼容；新增errors用于离线评测。
这是文字转写代理基线，不是声学声调检测。ASR纠错、同音字、多音字、轻声/变调、重复音节会影响结果。
没有识别到中文时明确失败，不伪装成“无错误”或“全部漏读”。不提供未经验证的F0分类器。
后续若声调漏检严重，再增加音节声学定位、基频提取与真实人工声调标签，并独立验证。

## 声调证据（2026-11-25 新增，默认关闭）
F0 判调在 25 条人工真值上只有 4/15 能判出的样本判对（27%），低于“全猜四声”的 48%，
因此**默认不计算、不返回、不报错**，文本层原有的 tone 错误（如 ASR 把“买”听成“卖”）保持不变。
需要用人工复核时再打开：
```powershell
$env:TONE_EVIDENCE="1"      # tokens[i].tone_evidence：expected/detected/confidence/reason/start_ms/end_ms/contour_st
$env:TONE_REPORT="strict"   # 额外允许高置信声调错；25 条上 0 条触发，不要当已支持
```
结论、失败原因和下一步见 [声调实验记录](声调实验记录.md)；复现脚本 `backend/tools/tone_experiment.py`。
不要在学生页面展示“声调已支持”，也不要拿这 25 条当准确率。

## 安装与批量运行
新电脑推荐Python 3.11或3.12；本机环境为3.12。
```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements.txt -r requirements-eval.txt
.venv/Scripts/python.exe -m pip install -r requirements-funasr.txt
./运行模型对比.ps1
```
CPU是便于先跑通的默认值。FunASR额外依赖较大；torch与torchaudio须匹配。
GPU不是把驱动版本当PyTorch版本；确认CUDA兼容后使用对应环境。Whisper GPU建议float16，CPU建议int8。
脚本默认串行三个模型，进程退出释放模型内存。首次耗时含下载，正式推理计时不含模型加载/转码。
没有安装某模型或加载失败会保存load_error.json，不会替换成其他模型或伪造结果。
FunASR不启用任意远程模型代码；若安装版本提示模型未注册，按官方说明安装兼容版本，不随意开启远程代码执行。

单独运行（工作目录backend）：
```powershell
../.venv/Scripts/python.exe -m app.benchmark run --manifest ../evaluation/candidates40/verified.jsonl --backend whisper --model small --out ../evaluation/runs/whisper-small-01
../.venv/Scripts/python.exe -m app.benchmark run --manifest ../evaluation/candidates40/verified.jsonl --backend sensevoice --out ../evaluation/runs/sensevoice-01
../.venv/Scripts/python.exe -m app.benchmark run --manifest ../evaluation/candidates40/verified.jsonl --backend paraformer --out ../evaluation/runs/paraformer-01
../.venv/Scripts/python.exe -m app.benchmark compare --runs ../evaluation/runs/whisper-small-01 ../evaluation/runs/sensevoice-01 ../evaluation/runs/paraformer-01 --out ../evaluation/runs/对比.md
```
每次out用新目录，避免覆盖结果。model可以指定本地模型目录；正式实验固定模型文件和revision，记录模型来源。
不同后端对数字、简繁体的处理可能不同；当前CER只统一NFKC/大小写/去标点空格，保留数字和拉丁字符。
CER=(替换+删除+插入)/参考字符数。报告全体成功样本的加权CER，不平均每句百分比。
RTF=识别耗时/音频时长，小于1代表快于音频播放。不同硬件不直接横比。
失败样本不进入CER，必须同时展示失败数；不按成功样本CER自动宣布最佳。
偏误匹配采用“类型+位置”，连续增读按一个边界事件计算，当前F1不评价actual音节内容。
诊断失败另列gold_failed。没有人工金标不计算四类指标。正确样本误报率仅对人工确认gold_errors=[]计算。
报告中的声调F1只能表示文本代理流程对声调标签的检出，不代表声学识别准确率。

## 加入你们自己的错读录音
另建 evaluation/known-errors/，复制录音，建立UTF-8 manifest.jsonl，一行一个JSON。
reference_text填写录音实际内容的人工转写；target_text填写要求读的题目，两者不要混淆。
声调读错但仍是同一汉字时，reference_text可以一样，gold_errors记录声调实际读音。
实际音频无法用汉字精确表示时，CER仅作辅助，偏误金标才是主要依据。
示例仅示范格式，不是已采集数据：
```json
{"sample_id":"student-001","audio_path":"audio/001.wav","reference_text":"你好","reference_verified":true,"target_text":"你好","tokens":[{"c":"你","py":"ni3"},{"c":"好","py":"hao3"}],"gold_verified":true,"gold_errors":[{"type":"tone","char_index":0,"actual":"ni2"}]}
```
四类名称tone/substitution/omission/insertion；插入用boundary_index，其余用char_index。
只有听过并确认才设置verified=true。未标注是null，确认正确才是[]。
同句重录、同一题重复朗读按group_id分组；调参数据和最终测试数据不要交叉。

## 文件说明
- backend/app/services/asr_backends.py：统一识别接口、懒加载、线程锁；`transcribe_with_words` 提供词时间戳。
- backend/app/services/alignment.py：拼音规范化与动态规划。
- backend/app/services/diagnosis.py：替换原基线，保持数据库返回字段；可选挂声调证据。
- backend/app/services/prosody.py、tone.py、tone_diagnosis.py：F0 特征、判调规则、时间戳对齐与高置信门控。
- backend/tools/tone_experiment.py：在人工真值上复现声调实验。
- backend/app/benchmark.py：数据准备、批处理、指标、跨模型对比。
- backend/app/review_dataset.py：离线试听与复核导入。
- backend/tests/test_algorithm.py：对齐、边界、失败和评分门槛测试。
- evaluation/：本地音频和结果，不提交Git。
- requirements-eval.txt、requirements-funasr.txt：分层依赖。
- 验证记录.md：本次实测范围，务必区分单元检查与真实模型评测。
