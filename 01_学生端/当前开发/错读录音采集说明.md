# 错读录音采集与评测（模型一配套）

> 目的：补上“标准听力音频测不出来的那一半”——**学生读错时，系统能不能判出来、会不会乱报**。

## 1. 两套数据，别混用

| | 标准音（已有） | 错读录音（要自己录） |
|---|---|---|
| 数据 | `evaluation/candidates40_v2/`，播音员 HSK 听力切片 | 人故意读错/正常读的录音 + 当场人工标错 |
| 回答的问题 | 模型**听标准普通话**准不准、快不快 | 模型**判偏误**查得全不全、报得准不准 |
| 指标 | CER、成功的样本数、RTF | 四类偏误的 P/R/F1、干净样本误报率、CER |
| 用来做什么 | 三人横比、选默认引擎 | 证明诊断功能有没有用 |

**为什么必须先有标准音那一轮**：如果模型连播音员的标准音都转写不对，它给出的“偏误”就只是它自己的听写错误。
所以顺序是：先用标准音选出“听得最准”的引擎，再用错读录音检验这个引擎的判错能力。

## 2. 录音方式（三种，按可行性选）

1. **自己录（今天就能做）**：用 `录音页.html`，20 句模板，每句可录“正常读 + 故意读错”，当场标错位置。
   缺点：是母语者的“故意错”，不是留学生的真实偏误分布；但足以验证“诊断链路能不能把错误抓出来”。
2. **找真留学生录（最有说服力）**：同样的 20 句 + 同一个页面，录真实偏误；注意知情同意、匿名编号。
3. **合成错读（最省人，最不真实）**：TTS 生成标准音后改声调/替换音素。只适合做鲁棒性压测，不能当真实数据写结论。

建议：今天先用方式 1 把链路跑通，方式 2 作为正式数据（找 2–3 位留学生，各 10 句）。

## 3. 怎么录（三步）

**打开页面**：

```
D:\大创\新的大创\pronunciation-platform-algorithm\01_学生端\当前开发\evaluation\known-errors\录音页.html
```

**每句流程**：

1. 选题目（20 句，来自题库，带拼音）
2. 选“这次录的是哪种”：正常朗读 / 声调读错 / 声母韵母读错 / 漏读一个字 / 多读一个音节
3. 点“开始录音” → 读完 → 停止 → **先听一遍**
4. 标错：点有错的那个**字**（按题目要求的字序），选实际声调或填实际读音；多读的点点字中间的 `+`
5. 点“保存这条样本”，接着录下一句

**每人录 10 句的配比**（三人同一配比，否则没法合表）：

| 类型 | 条数 | 说明 |
|---|---|---|
| 正常朗读 | 2 | `gold_errors=[]`，用来算**误报率**，不能只录错的 |
| 声调错 | 3 | 最常见：把二声读成三声、四声读成一声等 |
| 声母/韵母错 | 2 | 如 zh/z、n/l、in/ing 不分 |
| 漏读一个字 | 2 | 整字跳过 |
| 多读一个音节 | 1 | 句尾或字间加一个音节 |

**录音要求**：安静房间、手机/耳麦均可、离麦 15–20 cm、一句一次过、不要后期处理（不降噪不剪辑）。

## 4. 录完导入

页面点“导出采集结果”得到 `collect.json`，在 `01_学生端/当前开发` 下：

```powershell
$env:PYTHONIOENCODING='utf-8'
.venv\Scripts\python.exe evaluation\导入录音.py evaluation\known-errors\collect.json --out evaluation\known-errors --speaker s01
```

会生成 `manifest.jsonl`（含 `target_text`、`tokens`、`gold_errors`、`gold_verified=true`）和 `采集汇总.json`。
`--speaker` 填采集人编号，直接录音人用 `s01`、`s02`、`s03`，别重复。

## 5. 评测命令（和标准音同一套脚本）

```powershell
cd backend
..\.venv\Scripts\python.exe -m app.benchmark run --manifest ..\evaluation\known-errors\manifest.jsonl --backend whisper --model small --device cpu --compute-type int8 --out ..\evaluation\runs\whisper-small-errors-01
cd ..
.venv\Scripts\python.exe evaluation\计算报告卡.py evaluation\runs\whisper-small-errors-01
```

有金标时 `summary.json` 会多出 `error_metrics_success_only`（四类偏误的 tp/fp/fn/P/R/F1）和
`clean_false_alarm_rate`（正常朗读被误报的比例）。**这两个数才是“诊断能力”**，CER 此时只是副指标。

## 6. 已经跑过的一次自检（说明链路真的会出错、也会抓错）

用 1 条真实音频复制成 4 条（正常/声调/漏读/多读），跑出来后：

- `gold_samples=4`，`error_metrics` 非空 → 金标链路通
- `clean_false_alarm_rate = 1.0` → **唯一那条“正常朗读”被误报成漏读**

原因不是模型听错，而是标准音那一轮发现的同一个坑：Whisper 把“六分钟”写成“6分钟”，
诊断按拼音对齐时“6”不是汉字，被当成“漏了‘六’”。也就是说：

- 这一步自检证明**金标评测能暴露归一化/文字转写造成的假偏误**；
- 在录入真实错读之前，必须先修“中文数字/繁简”归一化，否则学生正常读也会被判错。

结论：**先修归一化，再录真实错读**，否则采集到的 F1 里混着假偏误，白录。
