## 2. 这次带来了什么

| 能力 | 状态 | 说明 |
|---|---|---|
| 三后端 ASR 可切换（whisper / sensevoice / paraformer） | 可用 | `ASR_BACKEND` 环境变量；默认 whisper small CPU int8 |
| 文本层偏误：增读、漏读、声母、韵母、同音异调 | 可用 | 加权拼音 DP + 音系细类；原有 `tokens.err` / `gap_errors` 字段不变 |
| CER、偏误指标、跨模型对比、人工复核导入 | 可用（离线） | `benchmark.py`、`review_dataset.py`，需要人工确认的 gold 才计分 |
| F0 声调证据 | **实验性，默认关闭** | 25 条真值上 F0 判对 4/15（27%），低于全猜四声 48% |
| 声调自动报错 | **未启用** | `TONE_REPORT=strict` 可开，但 25 条上 0 条触发；不建议现在给管理端当错误用 |

声调为什么没开：目标字多在句末，三声读成“半三声”（21），声学上就是降调，和四声 51 重叠；
F0 还有倍频跳变和切分误差。详细数据、失败原因、下一步见
[声调实验记录](声调实验记录.md)，逐条结果见 [声调实验-25条结果](声调实验-25条结果.md)。

## 3. 接口兼容性

- `diagnose()` 返回字段保持：`recognized_text`、`tokens`、`gap_errors`、`status`、`model_version`、`evidence_kind`、`limitations`。
- 数据库表结构没改，`diagnoses.tokens/gap_errors/model_version` 照旧。
- 只有打开 `TONE_EVIDENCE=1` 时，`tokens[i]` 多一个 `tone_evidence` 对象；不打开时响应与旧版逐字段一致。
- `04_接口说明/联调工具/integration/adapters.py` 会忽略 `tone_evidence`，现有转换不需要改。

`tone_evidence` 结构：

```json
{
  "expected": "shui3",
  "detected": "3",
  "confidence": 0.72,
  "reason": "先降后升",
  "start_ms": 1920,
  "end_ms": 2340,
  "contour_st": [-0.04, 0.4, -0.94, 3.74, 8.08]
}
```

## 4. 运行

```powershell
cd 01_学生端/当前开发
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
cd backend
..\.venv\Scripts\python.exe -m app.init_db
..\.venv\Scripts\python.exe -m app.import_questions
..\.venv\Scripts\python.exe -m app.build_pinyin
..\.venv\Scripts\python.exe -m uvicorn app.main:app --port 8000
```

打开 <http://127.0.0.1:8000>。默认 whisper small，首次会下载模型；没有模型文件时诊断任务会写 `failed` 和原因，不会伪造结果。

需要声调复核证据时再打开（会增加一次带词时间戳的转写）：

```powershell
$env:TONE_EVIDENCE="1"
```

- 35 项单元测试通过：`python -m unittest discover -s backend/tests -v`

- 三后端适配、失败计数、CER、人工标注门槛等旧测试全部保留。
- 浏览器录音、跨端联调本轮未复测，不能写成“已联调”。

## 6. 性能与依赖

- whisper small CPU：这批 2–3 秒录音约 1.5–2 秒/条；词时间戳与 F0 额外约 0.1–0.3 秒/条。
- 新增依赖 `parselmouth`（有 Windows wheel）；未安装时声调证据自动跳过，不影响文本诊断。
- `sensevoice` / `paraformer` 需要另装 `requirements-funasr.txt`，模型较大，按需启用。

## 7. 给管理端/系统端的建议

- 学生页面继续不展示诊断结果，和原约定一致；管理端展示时把 `tone_evidence` 标成“实验性声学证据”，不要计入错误数。
- 只有 `errors` 里的 `type=tone` 才是错误；目前它来自文本层（ASR 同音异调），不是 F0。
- 如果要演示声调，建议演示“证据 + 人工复核”，不要演示“自动判错”。
- 下一轮需要三端一起定的仍是：管理读取与音频授权、题目版本、统计回写（见 `04_接口说明/接口对齐报告.md`）。
