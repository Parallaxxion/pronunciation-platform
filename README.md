## 项目简介

以下摘自老师的[《任务书—音频数据采集系统 V6.4》](05_相关材料/项目任务书/任务书-音频数据采集系统-V6.4.docx)：

> 本期的任务是完成系统的学生子系统、命题子系统、管理端子系统的建设与集成，以实现音频数据采集：命题子系统产出分级跟读题库并提供题目抽取接口，学生子系统面向留学生完成注册、看题、录音与上传，并通过内置的基线诊断算法实现偏误自动检测；管理端子系统负责数据统计、核查与导出；音频数据按统一格式存档，供后续标注与算法训练使用。

本仓库对应上述第一阶段，后续阶段以老师另行发布的任务为准。

| 小组 | 第一阶段主要职责 | 交付与对接 |
|---|---|---|
| 学生端 | 注册与同意授权、按级看题、录音和上传、保留重录、基线偏误检测 | 接收命题题目；向管理端提供授权范围内的录音、元数据与诊断结果 |
| 命题端 | 分级题库；出题→校验→统计→补题→达标发布的流水线 | 向学生端提供已发布题目；结合录音覆盖情况改进抽题 |
| 管理端 | 数据管理、统计、录音核查、诊断展示、可撤销操作与导出 | 牵头三端整合、统一前端风格、协调数据契约和验收 |

老师第二周强调：命题端同时交付高质量分级题库；管理端加强整体整合；三端前端统一风格。我们以现有管理端 UI 为共同视觉基准，各组完善自身业务。学生页面本期不展示诊断结果，管理页面负责核查。

### 2. 第一次获取全部成果

参与开发建议使用 Git；只阅读材料可在 GitHub 点击 **Code → Download ZIP**，解压后同样拥有三组完整文件。

```bash
git clone https://github.com/Parallaxxion/pronunciation-platform.git
cd pronunciation-platform
```

后续命令默认在这个总仓库根目录执行。Windows 可以将 `python` 换成 `py -3`；macOS/Linux 可用 `python3`。联调建议 Python 3.11；公共工具和管理原型不需要第三方 Python 包，学生端与命题端分别创建独立环境。

### 3. 查看界面、运行服务

```bash
python 03_管理端/当前开发/prototype/server.py --open-browser
```

打开 <http://127.0.0.1:8765>；终端保持运行，按 Ctrl+C 停止。初次运行自动生成本地演示数据库。原型使用合成音频和构造偏误，不能据此判断算法准确率。

**统一 UI 组件预览：**

```bash
python 04_接口说明/联调工具/scripts/preview_ui.py
```

打开 <http://127.0.0.1:8790>。这个预览用于复用样式与偏误组件，不代表三个业务服务已接通。

```bash
# 学生组：进入后阅读 README.md
cd 01_学生端/当前开发
```

```bash
# 命题组：从总仓库根目录进入，阅读 README.md 和 backend/README.md
```

联调建议端口：学生 8000、命题 8001、管理 8765、UI 预览 8790。命题服务的 8001 启动命令见[联调步骤](04_接口说明/联调步骤.md)。归档中的旧克隆地址只用于追溯；获取、提交和协作方式以本页为准。

### 4. 每天如何开发与提交

先保存未提交的个人修改，再更新主分支并创建自己的功能分支：

```bash
git switch main
git pull --ff-only
git switch -c feat/student-question-integration
# 修改自己负责的文件，完成检查后逐项添加
git add 01_学生端/当前开发/backend/app/routes/questions.py
git commit -m "接入统一题目来源"
git push -u origin feat/student-question-integration
```

以上是学生端示例；其他组换成自己的分支名和文件路径。随后在总仓库发起 Pull Request（PR），写清任务编号、改动、接口影响、测试结果和阻塞项，请另一位相关成员核对后合并。

有写权限的成员推送自己的分支；没有写权限的成员可 fork 本公开总仓库，再向本仓库提交 PR。写权限需维护者按实际名单安排，目前没有自动邀请成员或设置强制分支保护。

如果某组暂时仍在原仓库工作，交接时提供来源 commit 和变更清单，由总仓库通过 `import/…` 分支比对合入。**不要整目录覆盖已修改的代码。** 当前不存在两个仓库之间的自动双向同步；每个任务开始时明确在哪个仓库开发。

### 5. 用飞书完成需求、联调与验收

| 入口 | 用途 |
|---|---|
| [三组协作手册](https://bnu-3dv-lab.feishu.cn/docx/ZkHQdpO3mooWRux7gbecZ04Vnyg) | 项目范围、三组职责、填写规则、交接链、待确认事项、会议纪要与每周归档模板 |
| [三组需求与联调台账](https://bnu-3dv-lab.feishu.cn/base/Hafcb3RXbaJaBCsfwMwcMoNknwf) | 新增需求、认领任务、更新进展和阻塞、关联交付、记录验收结果 |

**访问方式：两份内容均设为“互联网获得链接的人可编辑”，无需申请权限。** 如飞书提示登录，使用自己的账号登录即可。三个视图操作的是同一张表：「全部需求」查看所有事项，「按状态看板」查看进展与阻塞，「按承接组」查看各组承担的事项。双击记录查看完整内容。

1. **提出需求**：先搜索是否已有同类事项，再新增一条记录。沿用 INT、UI、STU、PRO、ALG、ADM、E2E 编号并顺延，填写提出组、承接组、输入与交付物、可复现的验收标准。每条对应一个可独立验收的结果。
2. **确认认领**：承接组与提出组确认范围，填写一位主负责人及双方约定的完成时间。未确认的人选和日期保持待认领、待双方确认。
3. **开发与对齐**：主负责人更新状态及「依赖与下一步」。涉及接口时，先核对[接口对齐报告](04_接口说明/接口对齐报告.md)，共同确认字段、认证、状态、错误和统计口径，再通过 PR 更新 `04_接口说明/`。
4. **交付与验收**：在「GitHub材料」补上实际 PR／commit 和验证证据，用同一题号、录音号联调。提出方填写「验收人、日期与结果」，通过后改为已验收。提交 PR 时写相同任务编号。
5. **会议与归档**：会议前各组更新台账；会后在手册第七节按日期追加纪要，记录决定、确认人及下一步。周末把已验收结果、关键结论与提交链接写回各组周次 README，完整模板见手册第八节。

状态按 **待确认 → 已认领 → 开发中 → 待联调 → 待验收 → 已验收** 推进；遇到依赖标记「阻塞中」并说明缺少什么、需要谁处理。取消或合并的事项保留记录和原因。初始 14 项依据现有成果整理，不代表各组已确认负责人、日期或验收。

飞书维护日常需求和会议结论；GitHub 保存正式代码、接口规范、测试证据和每周成果。原 `05_相关材料/协作对接/` 中的模板、约定与任务草表已迁移到飞书，仓库不再维护另一份动态台账，历史版本仍可在 Git 提交中追溯。

### 6. 每周如何留存成果

每组使用 **`YYYY.MM.DD-YYYY.MM.DD第N周`** 命名。当前按 11 月 9 日任务发布周起算：第一周 11.09–11.15，第二周 11.16–11.22，第三周 11.23–11.29。此为仓库整理规则，**不代表老师已确认最终截止日**。

- `当前开发/`：持续修改的代码；每周不搬家、不改运行路径。
- 周次目录：放当周 README、汇报材料、测试证据和需要留存的成果快照。
- 每周 README 写清：完成了什么、负责人、对应总仓库 commit/PR、运行与验证、尚未完成、下周计划。
- 周末归档前先去掉运行数据库、真实录音、密钥、虚拟环境和缓存；归档后保留原文件，补充说明另写文件。
- 管理组第一周汇报日期为 **11 月 16 日**，汇报材料仍归入第一周成果。学生端和命题端当前取得的是 **11 月 18 日版本**，归入第二周；第一周目录已注明尚无独立周末版本，未把后来成果倒填为第一周完成。

每周 README 模板见[飞书协作手册](https://bnu-3dv-lab.feishu.cn/docx/ZkHQdpO3mooWRux7gbecZ04Vnyg)第八节。初始快照的来源与哈希见[来源与核验](05_相关材料/来源与核验/)。

### 7. 提交前检查

在总仓库根目录执行：

```bash
python -m unittest discover -s 04_接口说明/联调工具/tests -v
python 04_接口说明/联调工具/scripts/check_algorithm_kit.py
python 04_接口说明/联调工具/scripts/check_repository.py
```

这些检查覆盖公共适配逻辑、合成 WAV 规格、初始归档完整性、交接包和文档导航。各组还需执行本组的业务检查；它们不替代真实服务联调或算法准确率评估。归档校验针对固定历史快照，允许“当前开发”正常迭代。

公开仓库只保存可公开代码和构造样例；真实学生录音、邮箱与个人信息、访问令牌、邮件密码和运行数据库留在授权存储中。学生端这份源码副本已经明确授权公开。各原作者的成果与来源均保留；本仓库没有代原作者添加开源许可证。
