# 三端接口说明

这里集中维护三组共同使用的数据约定、接口差异、样例和联调方法。**先看现状，再确认契约，最后按步骤接入真实服务。** 本版数据契约为 0.2 讨论稿；适配代码已实现，不等于建议中的 HTTP 接口已经上线。

| 阅读顺序 | 内容 |
|---|---|
| 1. [接口对齐报告](接口对齐报告.md) | 根据三组源码核对现有 API、字段差异和待新增接口 |
| 2. [数据契约](数据契约.md) | 题目、拼音、录音、诊断索引、状态、统计与版本语义 |
| 3. [JSON 示例](示例/) | 上游输入与规范化输出，可用于对照字段 |
| 4. [联调步骤](联调步骤.md) | 本地检查、服务端口、接入顺序与真实验收 |
| 5. [联调工具](联调工具/README.md) | 适配器、检查脚本、测试和运行命令 |
| 6. [兼容补丁](兼容补丁/README.md) | 命题前端 `items` 读取的最小补丁及应用方式 |

## 三条重点交接链

| 提供方 → 使用方 | 需要交付 | 当前重点 |
|---|---|---|
| 命题端 → 学生端 | 已发布题目、逐字拼音、稳定题号与版本 | 从服务取题并保存题目快照 |
| 学生端 → 管理端 | 授权录音列表、音频、元数据与诊断结果 | 管理角色认证、跨用户权限和偏误索引 |
| 管理端 → 命题端 | 按题覆盖统计、独立说话人数与版本 | 幂等更新，重试、删除、恢复不造成多计 |

统一 UI、算法音频和下载包在[相关材料](../05_相关材料/README.md)。需求认领、阻塞与验收记录在[协作对接](../05_相关材料/协作对接/README.md)。

修改接口时，在同一 PR 更新字段说明、输入输出示例和受影响测试，列明兼容方案，由相关组共同确认。讨论项写明待确认；正式定稿再更新版本号和生效日期。
