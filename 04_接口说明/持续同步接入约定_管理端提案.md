# 持续同步接入约定：管理端已实现，待学生组确认

日期：2026-11-25。**这是一份可执行的管理端接入契约，不是三组已经达成一致的接口。** 不要求学生组照搬内部数据库结构：若已有管理员接口，管理组写适配器转换成以下批次即可。真实接口地址、服务身份、授权样例、分页和来源版本由双方确认后再启用定时任务。

管理端代码：`03_管理端/当前开发/backend/synchronization.py`、`sync_worker.py`。本机演练使用明确标为合成数据的契约服务，不读取学生生产数据库，不把学生本人身份当管理员。

## 1. 管理端接收接口

- `POST /api/v1/admin/integration/batches`：需要管理员身份和 `Idempotency-Key`，单次最多 100 事件、请求体最多 4 MiB；整个批次在一个事务中提交，任一错误全部回滚。
- `GET /api/v1/admin/integration/sources/{source_id}`：管理员查询已提交游标；首次为 `null`。
- 音频沿用 `POST /api/v1/admin/audio?variant=wav|original`，先上传、校验哈希，再提交引用音频的批次。未关联的音频不会计入录音数量。

```json
{
  "schema_version": 1,
  "source_id": "student-main",
  "batch_id": "batch-000001",
  "cursor": null,
  "next_cursor": "cursor-000001",
  "events": [
    {
      "event_id": "speaker-S001-v1",
      "kind": "speakers",
      "entity_id": "S001",
      "source_version": 1,
      "operation": "upsert",
      "data": {
        "speaker_id": "S001", "nationality": "授权背景",
        "language": "授权母语", "level": 1, "source": "student"
      }
    }
  ]
}
```

| 字段 | 约定 |
|---|---|
| source_id | 稳定且唯一的来源名称；数据库更换或重建需人工确认，不随重试变化 |
| batch_id / event_id | 来源内稳定唯一；重试复用，不能用于不同内容 |
| cursor / next_cursor | 不透明游标，只比较相等；发送端必须保留可重放的变更记录。非空批次必须推进游标 |
| kind | `speakers`、`questions`、`recordings`；先提交说话人和题目，再提交引用它们的录音 |
| source_version | 单实体严格递增的正整数；不可用客户端时间或管理员本地 version 代替 |
| operation | `upsert`、`delete`、`restore`；删除/恢复只带身份和版本，`data=null` |
| data | 使用管理 API 的 Speaker、Question、Recording 输入结构；模型细节见 OpenAPI 与 `contracts.py` |

机器可读结构：[同步批次 JSON Schema](同步批次.schema.json)、[学生变更页 JSON Schema](学生变更页.schema.json)。`data` 的实体结构按 `kind` 由服务端进一步校验。现有 [数据契约](数据契约.md) 中的逐字索引和拼音约定继续使用。

成功回执包含 `source_id`、`batch_id`、提交后的 `cursor`、`payload_sha256`、逐事件结果和 `batch_replayed`。哈希是管理端规范化模型完整 JSON 的 UTF-8 SHA256：键排序、无多余空格、保留非 ASCII 字符；可直接使用仓库 `synchronization.digest`，不要自行猜省略字段规则。拉取工具会核对回执；对方无需重新实现管理回执哈希。

## 2. 哪些更新可以自动应用

1. 相同批次重试返回原回执；相同事件或相同来源版本、相同内容不会重复创建。并发提交由 SQLite 事务串行裁决。
2. 旧来源版本、同版本不同内容、同事件编号不同内容、游标不匹配返回 409，不跳过错误记录推进游标。
3. 新来源不能自动接管已存在的管理记录或其他来源记录。遇到同名编号，由两组核对映射，不能直接覆盖。
4. 录音身份、说话人、题目、练习次数、音频哈希和录音时题目快照不可被后续同步改写。算法状态与结果可更新，人工核查备注保留。
5. 管理员已经修改诊断时，同步会报告冲突，避免覆盖人工修正。题目/说话人的管理修改、来源删除/恢复与本地修改冲突时同样停止，人工确定权威版本后再处理。
6. 删除必须显式发送事件，列表里“没出现”不等于删除；旧创建批次重放不会复活记录。恢复必须显式发送。活跃录音数量随删除/恢复变化。
7. 非合成录音必须带授权依据编号 `consent_reference`。真实邮箱、口令和其他个人资料不放在公开交接 JSON；音频只走受限服务或授权文件包。

冲突处理：保留失败批次、核对来源版本与管理历史，明确谁修改了什么；修正来源内容或经管理员在管理端进行可审计的恢复/修订后重试。不要直接编辑数据库游标、删除去重表或重用旧版本号。

## 3. 学生组可选择提供的变更页

`sync_worker.py student` 只调用学生组明确给出的 `--feed-path`，不会默认猜测 `/admin/...` 路径。请求携带专门的 `STUDENT_SERVICE_TOKEN`，参数为 `limit=100` 及接收端已提交的 `cursor`；首次没有 cursor 参数。

```json
{
  "source_id": "student-main",
  "batch": {"schema_version":1,"source_id":"student-main","batch_id":"...","cursor":null,"next_cursor":"...","events":[]},
  "audio": [{"sha256":"64位小写SHA256","variant":"wav","path":"/已确认的受保护音频路径"}],
  "has_more": false
}
```

上面仅展示层级，省略号与空 `events` 不是可提交样例。完整可运行样例由 `backend/tests/rehearse_handoff.py` 生成。

没有新增变更时返回 `{"source_id":"student-main","batch":null,"audio":[],"has_more":false}`。有批次时必须非空，且起始游标匹配请求。录音 upsert 对应的 `wav/original` 哈希都必须在音频清单内；相同哈希和类型可复用一项。路径必须是同一服务内的相对路径，不能是另一个域名或重定向；每个文件不超过 20 MiB。标准 WAV 为 16 kHz、单声道、16 bit PCM。

工具先下载并验证 SHA256，再向管理端提交；失败不推进游标。一次最多取 10 页，剩余页由下一次运行继续处理。网络错误、429、502/503/504 有限重试并保留同一幂等编号；401/403/409/422 直接失败等待处理，不无限循环。

## 4. 命题覆盖回传

沿用现有 `PUT /api/v1/integration/coverage`。管理端将快照在请求前持久写入私有 SQLite 日志；失败或回执不匹配保持 pending，下次先重发原快照，不以新快照跳过失败项。进程崩溃后锁自动释放；并发任务不重复发送不同版本。日志绑定目标服务，换目标必须明确使用新日志。

只有回执 `ok=true`、`applied` 为布尔值且 `snapshot` 与发送内容完全相同时，日志标为 **received（已接收）**。这个状态不表示命题 `rec_count` 已采用。旧版本拒绝、跨实例切换、实际计数应用和推荐均衡仍由命题组实现并联合验收。

## 5. 交付到货后如何接

1. 取得固定提交、启动命令、管理服务身份、完整请求响应及一条授权录音；先确认接口范围。
2. 若已提供上述变更页，配置真实路径即可试运行；若接口格式不同，在管理组适配层转换，保留双方原始字段和版本信息。
3. 先手动跑一轮：新录音 → 管理详情/回放 → 诊断状态更新 → 人工备注不丢失 → 删除/恢复 → 导出 → 覆盖回传。
4. 完成重复请求、回执丢失、旧版本、非法音频与权限测试后再启用定时器。
5. 飞书当周表写真实提交和验收证据。当前只能确认“管理接收器和参考契约演练完成”，不能确认“学生真实接口对接完成”。
