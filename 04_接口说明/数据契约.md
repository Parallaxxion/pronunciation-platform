# 公共数据契约

版本为0.2讨论稿。适配器已实现，跨组接口与统计口径仍需负责人确认。所有JSON样例均为独立构造数据。

## 题目

`question_id`保留来源ID；`question_version`由命题端提供，缺失时为null；`content_revision`是本版题文与规范拼音的SHA256，用于发现内容变化，不能代替发布版本。`display_text`保留标点。`tokens`按发音字顺序包含`c`、`py`、`display_py`、`display_start`。

计算拼音`py`采用小写带数字声调，轻声5，ü写v。页面使用`display_py`保留原带调写法。规范化只处理编码，不判定多音字、变调或拼音在教学意义上是否正确。整句拼音缺少逐字对应时拒绝猜测。

`display_start`按Unicode码点定位原文；JavaScript使用`Array.from(text)`。`char_index`引用tokens，`boundary_index=k`位于tokens[k]之前，0表示句首，tokens.length表示句尾。不是UTF-16下标，也不是含标点的原文下标。

## 录音与音频

| 字段 | 规则 |
|---|---|
| recording_id | 每次录音稳定唯一；上传重试不新建 |
| speaker_id | 匿名学生ID，不导出邮箱或真实姓名 |
| question_id | 来源题号 |
| question_snapshot | 提交时完整题目、逐字拼音及内容摘要 |
| practice_session_id | 所属练习记录ID |
| take_no | 该练习内第几次录音，不等于跨练习全局次数 |
| recorded_at | 带时区ISO 8601 |
| device | 必要设备信息对象 |
| upload_status | uploaded等明确状态 |
| deleted | 是否逻辑删除 |
| wav_url / original_url | 授权地址；不含本地服务器绝对路径 |

交接包标准WAV为16kHz、单声道、16-bit PCM。这是本次算法接口适配规格，原始文件另存。是否作为最终统一存档规格需三组确认。

## 诊断

统一`status`为pending、processing、completed、failed。只有completed且errors为空，才表示本次模型未检出偏误。保留model_version；error_message展示前需去除凭证和内部路径。

errors每项包含type、位置、expected、actual。type取tone、substitution、omission、insertion。前三种使用char_index；insertion使用boundary_index。漏读actual为null，增读expected为null；多个增读音节按空格连接。允许同一位置多类错误。

现有输入的`done`转换为completed；`err.t`的sf/del映射为substitution/omission；`gap_errors`的ins映射为insertion。转换只保留上游已提供的信息，不能恢复上游丢失的增读音节。

## 统计与回写

recording_count统计已上传、未删除的不同recording_id。unique_speaker_count单独计算。重复的同ID同内容记录去重，同ID不同内容的快照拒绝并要求调用方先确定最新版本。未确认采集目标时target_recordings与gap均为null。

建议采用带版本覆盖快照：`{snapshot_version, generated_at, items:[{question_id, recording_count, unique_speaker_count}]}`。接收方校验版本、题号与授权，整批应用；重复版本不累加，过期版本拒绝。同一逻辑也要涵盖删除、恢复。此回写服务尚待实现，当前适配函数只计算结果，不写上游。
