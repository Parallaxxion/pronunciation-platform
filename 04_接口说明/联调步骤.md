# 联调步骤

先完成本地适配与样例验证，再接真实服务，最后进行HTTPS设备录音。每次记录总仓库提交与来源版本、服务地址和测试账号角色；不用真实姓名作录音标识。

## 本次可复现检查

1. `python -m unittest discover -s 04_接口说明/联调工具/tests -v`，验证题目、诊断、索引、统计与音频包。
2. 执行04_接口说明/数据契约.md中的两个本地JSON转换命令，检查输出。
3. `python 04_接口说明/联调工具/scripts/preview_ui.py`，查看原风格和统一偏误组件。
4. `python 04_接口说明/联调工具/scripts/check_algorithm_kit.py`，验证4条合成音频的规格、哈希与关联。

## 命题API接入

在02_命题端/当前开发目录中按其README创建独立环境、初始化与导入题库。使用8001避免与学生端8000冲突：

```bash
python -m uvicorn backend.main:app --host 127.0.0.1 --port 8001
```

题目由命题负责人完成校验与发布。回到总仓库执行只读 `04_接口说明/联调工具/scripts/fetch_questions.py`。若返回空列表，核对是否已发布；不要把未发布题目强行标成published。已下载JSON存local-data，不自动进入Git。

## 学生与管理接入

学生服务通常运行8000；管理原型8765。学生组先将命题题目接入练习创建，再上传经授权录音，取得recording_id。算法服务完成诊断后，管理组使用约定的管理员身份读取，不借用学生账号跨用户查询。

当前需要补充的跨用户列表和音频接口见接口报告。不要直接连接另一个组的数据库写入。取得这些接口前只能报告样例验证完成，不能报告真实全链路完成。

## 真实验收顺序

1. 一个已发布题目带正确逐字拼音进入学生页面。
2. 首次录音、重录各保留独立ID；同一次断网补传不重复计数。
3. 四类偏误的已知测试录音产生可追踪结果；与人工预期分开保存。
4. 管理端查询、回听、按token显示偏误；pending和failed有明确提示。
5. 删除和恢复后列表、录音量、独立说话人数与导出一致。
6. 复制整个导出包到独立目录，用脚本验证路径、哈希、WAV规格、题目快照与标注关联。
7. 在约定HTTPS域名上验证真实设备录音、会话、权限和音频访问。

统一前端部署建议预留 `/student/`、`/proposition/`、`/admin/` 业务入口以及对应服务API前缀。该路由规划尚未配置，须结合统一登录方案落地；浏览器跨域Cookie不能仅凭三个页面风格一致就认为可互通。
