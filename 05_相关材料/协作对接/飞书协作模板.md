# 飞书三组协作空间模板

建议名称：**中文发音诊断与评价系统｜三组需求与联调**。

采用一份共享说明文档，加一张多维表格。初期手动填写 GitHub PR 与验收链接即可，不依赖机器人或自动同步开发。以下模板已按当前项目填入初始事项；个人负责人、日期由各组实际确认。

## 搭建方法

1. 在三组方便共同访问的飞书空间中新建说明文档，将下方“共享文档正文”复制进去。
2. 新建一张多维表格，参考下方字段表建“需求与联调”数据表，再录入初始事项。可以先用普通文档表格起步，任务增多后再转多维表格。
3. 建三个视图：全部需求、按承接组分组、按状态分组。需要时增加“阻塞中”筛选视图。
4. 三组成员设为可编辑，老师/师兄根据实际需要设为可阅读或可评论；邀请操作由文档维护者执行。
5. 在说明文档中放多维表格链接，在总仓库“协作对接”README 中填回实际飞书地址。

飞书官方说明支持按进度、负责人组织多维表格和看板，适合这个场景：[多维表格项目管理说明](https://www.feishu.cn/hc/zh-CN/articles/868158430248-%E5%A4%9A%E7%BB%B4%E8%A1%A8%E6%A0%BC-%E9%87%8D%E5%A1%91%E9%A1%B9%E7%9B%AE%E7%AE%A1%E7%90%86%E6%B5%81%E7%A8%8B)。具体分享范围以所在飞书空间的权限为准。

## 共享文档正文（可复制）

### 我们共同完成什么

第一阶段建设学生端、命题端和管理端，跑通“分级命题 → 学生录音与诊断 → 管理核查统计 → 标准导出”。管理组牵头整合，三组沿用统一 UI 风格，各自负责业务实现。

- 总仓库：https://github.com/Parallaxxion/pronunciation-platform
- 接口说明：总仓库 `04_接口说明/README.md`
- 统一前端：总仓库 `05_相关材料/统一前端/README.md`
- 算法样例：总仓库 `05_相关材料/算法交接样例/README.md`
- 需求与联调多维表格：待创建后填写真实链接。

### 需求如何流转

**待确认 → 已认领 → 开发中 → 待联调 → 待验收 → 已验收**。遇到外部依赖可标“阻塞中”，同时写依赖谁、缺什么、下一次检查时间。

每条任务有唯一编号，沿用 INT、UI、STU、PRO、ALG、ADM、E2E 前缀。每条需求由提出组说明验收标准，由承接组确认负责人和时间。跨多组的大需求拆成可分别验收的小任务。

“文件已提供”“样例转换通过”“真实接口通过”“真实算法效果通过”分开记录；只有提出方按约定验收后才标已验收。

### 字段建议

| 字段 | 建议类型 | 如何填写 |
|---|---|---|
| 任务编号 | 文本 | 如 STU-02，与 GitHub PR 对应 |
| 需求标题 | 文本 | 一句话说明交付结果 |
| 提出组 | 单选 | 学生端／命题端／管理端／共同 |
| 承接组 | 单选或多选 | 实际承担实现的小组 |
| 负责人 | 人员 | 本人确认后填写；尚未认领留空 |
| 优先级 | 单选 | P0 阻塞主链路；P1 本阶段必需；P2 后续改进 |
| 状态 | 单选 | 待确认、已认领、开发中、待联调、待验收、已验收、阻塞中 |
| 输入与输出 | 多行文本 | 字段、示例、数据规格、接口调用方向 |
| 验收标准 | 多行文本 | 可复现步骤与预期结果 |
| 计划完成时间 | 日期 | 双方确认后填写，不猜测老师截止时间 |
| 阻塞与下一步 | 多行文本 | 缺什么、谁来补、何时复查 |
| GitHub PR/文档 | 链接 | 正式接口、实现和测试证据 |
| 验收人及结果 | 多行文本 | 提出方、提交版本、检查日期与实测 |
| 最近更新 | 日期 | 最后一次人工更新日期 |

### 初始事项（可录入）

下表优先级是协调建议，负责人和日期尚待各组确认。已交付样例的任务仍需接收方验收。

| 编号 | 需求标题 | 提出组 → 承接组 | 建议优先级 | 当前台账状态 | 交付与验收 |
|---|---|---|---|---|---|
| UI-01 | 复用管理端 UI 基线与偏误组件 | 共同 → 三组前端 | P1 | 待验收 | 交接包已准备；接收组能启动预览并确认配色、布局和偏误展示 |
| UI-02 | 明确公共前端负责人及三端统一入口 | 共同 → 三组确认 | P1 | 待确认 | 选定负责人、路由与登录方案；三端沿用统一样式，学生不展示诊断 |
| STU-01 | 学生端改为从命题服务取已发布题 | 管理端 → 学生后端、命题后端 | P0 | 待确认 | 新发布题无需手工复制即可使用；练习保存题号、版本和题目快照 |
| STU-02 | 管理角色读取录音、音频及诊断 | 管理端 → 学生后端 | P0 | 阻塞中 | 管理员按授权范围查询；学生不能跨用户读取；状态与音频可追溯 |
| PRO-01 | 命题前端适配列表 items 字段 | 共同 → 命题前端 | P1 | 待确认 | 最小补丁已提供；对真实后端非空列表可正常显示 |
| PRO-02 | 确认题目版本与覆盖统计回写 | 共同 → 命题后端、管理统计 | P0 | 待确认 | 重试不多计，删除恢复可同步，独立说话人数单独统计 |
| ALG-01 | 读取标准音频与拼音，返回约定诊断格式 | 学生算法 → 管理组、学生算法 | P1 | 待验收 | 格式包已提供；16k/mono/16bit可读，recording_id及错误位置正确关联 |
| ALG-02 | 准备已知错读实录与人工预期结果 | 共同 → 算法组牵头 | P1 | 待确认 | 四类偏误及句首句尾案例有实录、人工预期和单独算法输出 |
| E2E-01 | 完成一条录音全链路联调 | 共同 → 三组 | P0 | 阻塞中 | 同一题号/录音号贯穿取题、录音、诊断、核查、统计与导出；依赖 STU-01/02、PRO-02 |

STU-02 当前缺少确认后的管理角色与读取接口；E2E-01 依赖前述真实接口接入。这里“阻塞中”描述集成现状，不代表对方已承诺任务或超期。管理组内部 ADM-01/02/03 等任务继续从 GitHub 第二周看板按需录入。

### 每次对接会议记录

- 日期与参会人：
- 本次检查的任务编号：
- 已演示的版本与结果：
- 达成的接口或业务结论：
- 未决定的问题及需谁确认：
- 下一步动作：任务编号／负责人／双方确认时间／验收标准。

会后将正式接口变化写入 GitHub PR；每周将已验收结果和关键结论留存到小组周次 README。飞书不另建一套不同版本的接口字段表。
