# 三组协作与需求对接

代码和正式接口以本 GitHub 总仓库为准；日常需求、认领、阻塞、会议结论可以由三组共同维护在飞书。两处用相同任务编号关联，避免把完整接口规范来回复制。

| 入口 | 用途 |
|---|---|
| [飞书协作模板](飞书协作模板.md) | 可复制的首页、需求台账、会议纪要和搭建步骤 |
| [第二周任务看板](第二周任务看板.md) | 当前已有的跨组事项与验收要求 |
| [每周归档模板](每周归档模板.md) | 各组周末留存成果时使用 |
| [协作约定](协作约定.md) | 分支、PR、公共接口、来源同步等规则 |

**飞书在线入口：待创建。** 本次已准备模板和初始任务，没有创建在线文档，也没有向任何成员发送邀请。创建后由维护者在本页填写实际链接；飞书提供日常状态，GitHub 保留正式成果和按周结论。

## 对接规则

1. 提出需求：说明为什么需要、期望拿到什么、输入输出示例和怎样算完成。
2. 对方确认：承接组填写实际负责人和双方约定时间；未确认不能写成已认领。
3. 开发联调：提交代码或接口 PR，更新状态与阻塞原因。
4. 共同验收：需求提出方按标准复现，记录 commit、步骤和结果；通过后标记已验收。
5. 每周留存：各组将本周结论和验收链接写入周次 README，必要时保存飞书台账导出副本，保持可追溯。

管理组负责推动对接，各组仍负责自己的实现与测试。共同前端维护人需要三组确认；现有 UI 基线已经准备，但不代表整合后的业务界面已经完成。
