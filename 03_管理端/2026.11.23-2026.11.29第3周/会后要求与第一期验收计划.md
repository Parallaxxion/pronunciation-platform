# 第三周会后要求与第一期验收计划

记录日期：2026 年 11 月 23 日。依据：闫晓奕会后转述的师兄要求及本期任务书。第三周为 11 月 23 日至 29 日，下周进行第一期验收，具体会议时间以通知为准。本文件记录交付目标与执行计划，不表示以下功能或测试已经完成。

本周优先保证管理组交付质量，同时完成三组前端整合与部署。前端整合、上游接口对接、部署和测试并行推进；此前“等三组材料全部到齐再整合 Web”的安排由本计划替代。先搭建统一业务流程和接口适配，再逐项接通真实服务；演示数据与真实数据必须明确区分。

## 两套完整三端前端

师兄要求下周前提供完整三端前端演示并部署；闫晓奕进一步决定同时完成两套版本。两套都包含学生端、命题端、管理端，并按同一份功能清单验收。

| 版本 | 界面依据 | 交付要求 |
|---|---|---|
| 师兄风格版 | 工作区的《中文发音智能诊断与评价系统-演示V2demo.zip》 | 延续可用的视觉和交互，补齐本期三个子系统与真实业务接入 |
| 管理组风格版 | 第一周管理组界面及仓库中保存的基准 | 保留已经认可的布局、配色和偏误展示，扩展到三个子系统 |

两套界面共用业务逻辑、接口适配、权限规则和自动化业务测试；分别检查布局、交互、错误提示与功能完整性。提供两个清楚的访问入口或可切换的版本入口，切换风格不改变数据和权限。最终代码组织方式在核查三组现有代码后确定。

师兄 V2 包的 README 明确说明它是无后端、无真实算法、刷新重置的演示，角色是学生、教师研究员、管理员。不能把它直接当成本期已经完成的学生、命题、管理三端系统。命题流水线需要实际接入；其中学生评分、诊断反馈、班级、作业等演示功能按本期任务书取舍。本期学生端不展示诊断或评分，诊断结果在管理端查看。

## 必须完成的业务范围

| 范围 | 验收内容 |
|---|---|
| 公共入口 | 三端导航和角色权限明确；登录、退出、会话过期、禁止访问可正确处理；页面刷新和直接访问子页面可用 |
| 学生端 | 注册与录音用途同意、等级抽题、逐字拼音、录音试听重录、保留每次录音、上传与断网补传、上传状态；保存题目版本和快照；本期不向学生展示诊断评分 |
| 命题端 | 题目管理、生成或导入、校验、统计、缺口补题、重新校验与发布；按等级抽题；录音覆盖回写真正影响业务计数；展示失败原因和不达标项 |
| 管理端 | 用户、题目、录音管理；按学生或题目筛选及回听；原始音频和标准 WAV 关联；诊断状态与逐字及字间偏误；修改删除撤销、权限、审计和版本冲突；采集统计、缺口分布、完整导出 |
| 跨端流程 | 同一题号与录音号贯穿发布、抽题、真实录音、上传、诊断、管理核查、统计和导出；刷新或服务重启后记录仍在，导出与界面及存储一致 |

两个版本都检查加载、空数据、无权限、请求失败、超时、网络中断及重试状态，避免按钮无效、假成功或失败后丢失录音。

## 部署交付

- 明确实际服务器、运行版本、域名或访问地址与 HTTPS 配置；保存启动、停止、升级、回滚说明。11 月 24 日前先确认可用资源，有资源后尽早做 HTTPS 真机录音。
- 前端与后端配置分离，业务代码不写死本机路径或地址；提供无实际凭据的配置模板、依赖版本和数据库初始化说明。
- 核对跨域或反向代理、会话、上传大小、请求超时、音频存储权限、持久化目录、日志与健康检查。
- 用新的浏览器会话和另一台设备访问实际部署地址，完成注册或登录、麦克风授权、录音上传、管理回听与导出。
- 在干净目录或新环境按说明复建一次，验证数据备份恢复和版本回退。保留演示备份，但备份不能替代在线部署验收。

## 软件工程测试

以任务书条目映射测试用例，每条记录前置条件、输入、操作、预期、实际结果、环境版本、代码提交和证据位置。缺陷记录复现步骤、影响、修复提交与复测结果。测试随开发执行，功能冻结后再做完整回归。

### 测试层次

| 层次 | 重点 |
|---|---|
| 单元与组件 | 状态转换、字音索引、标点及增漏读、空结果、统计计算、导出清单、输入校验 |
| API 与契约 | 必填字段、版本与快照、鉴权、错误响应、分页筛选、重复提交、幂等、冲突、历史记录及撤销 |
| 服务集成 | 真实命题到学生取题、学生数据到管理端、诊断存储与展示、覆盖回写后的业务计数；核对删除与恢复后的计数 |
| 浏览器端到端 | 两套界面分别完成本期流程；真实 HTTPS 录音、试听、重录、补传、回听、核查及导出；保存可复查的操作记录 |
| 安全与健壮性 | 角色越权、令牌过期、非法输入、路径访问限制、损坏或超限音频、重复上传、并发修改、服务中断及恢复 |
| 性能与稳定性 | 按确认的采集规模测并发录音上传、分页查询、批量导出和持续运行；记录负载、响应时间、错误率及资源占用。容量目标须先确定，不能只给无负载依据的“通过” |
| 部署与恢复 | 干净环境复建、依赖锁定、HTTPS、重启持久化、备份恢复、升级回滚 |

### 环境覆盖计划

| 环境 | 检查范围 | 执行要求 |
|---|---|---|
| Windows 与 Chrome、Edge | 两套界面的完整三端流程、麦克风与上传、回听导出 | 借用组员实际设备，记录系统及浏览器具体版本 |
| macOS 与 Chrome 或 Edge、Safari | 相同核心流程，重点检查录音格式、授权与播放 | 真浏览器实测；自动化 WebKit 结果不能替代 Safari 真机结果 |
| 实际部署服务器 | 安装启动、HTTPS、持久化、重启、备份恢复和目标负载 | 记录真实操作系统与运行时版本，不把本机通过当服务器通过 |
| 常用窗口尺寸与缩放 | 两套界面的导航、表格、弹窗、按钮和长文本 | 覆盖笔记本与桌面窗口，检查缩放后可操作性 |
| 网络与设备异常 | 断网恢复、弱网、超时、拒绝麦克风、无麦克风、设备切换 | 验证提示、数据保留、重试与不重复入库 |

本期为网页交付。移动浏览器是否属于正式支持范围需与实际采集设备一致；若纳入，补充 Android Chrome 和 iOS Safari 真机录音测试。未执行的环境标记“未验证”，不写“各种环境保证无问题”。质量结论必须写明已验证的支持范围与仍存在的限制。
