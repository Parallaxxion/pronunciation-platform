# 三端统一 Web

2026-11-25：第一周青绿风格与师兄 V2 学院蓝风格使用同一套业务代码、接口和数据。入口在管理服务根路径；右上角可以切换，`?theme=senior` 可直接打开学院蓝版。原型保留，不再作为完整三端入口。

## 当前能做什么

| 工作区 | 已接入的操作 | 仍依赖上游的部分 |
|---|---|---|
| 学生 | 注册、邮箱验证、登录登出、按等级请求题目、带调拼音、录音试听、重录留存、文件上传、浏览器草稿与补传、回执 | 当前学生服务仍从本地一级库取题；不可变题目快照、服务端历史、正式隐私协议与 SMTP 需交接 |
| 命题 | 题库列表、等级切换、校验、覆盖统计与缺口、发布门禁、已发布题目抽取预览、JSON 导出 | 网页新增/编辑/导入题目的上游接口，覆盖业务计数应用与版本冲突处理 |
| 管理 | 管理/只读登录、说话人与题目增改、录音筛选回听、四类偏误与状态、备注核查、历史、软删除恢复、撤销、统计、完整音频和标注导出 | 学生服务的管理员跨用户接口、真实诊断交付、注册人数统计、正式部署 |

学生入口不开放诊断、评分或偏误展示。页面不会把失败、无结果或未确定目标显示成正常结果或零缺口。

## 从总仓库启动本机演示

在总仓库根目录执行（Python 3.12 或兼容版本；本次实际使用 macOS / Python 3.14）：

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r '03_管理端/当前开发/web/requirements-demo.txt'
.venv/bin/python '03_管理端/当前开发/web/run_demo.py' --port 8891
```

Windows 实机复测按[Windows 启动与验收说明](../../2026.11.23-2026.11.29第3周/Windows启动与验收说明.md)执行；目前留待闫晓奕在另一台电脑操作，不以自动测试代替浏览器和麦克风验收。

- 青绿版：`http://127.0.0.1:8891/`
- 学院蓝版：`http://127.0.0.1:8891/?theme=senior`
- 启动器占用 8891、8892、8893；只监听本机，终端保持运行，Ctrl+C 同时停止三个服务。
- 管理令牌随机生成，启动器只打印本机文件位置。打开该文件复制到管理登录框，不上传 GitHub，不写进飞书。
- 学生端使用测试邮箱自行注册；本机无邮件配置时页面提供“完成本机测试邮箱验证”。正式环境必须通过真实邮件验证。
- 启动器默认复制学生当前源码及命题第三周固定快照到 `../local-data/portal-demo`，不会修改组员源码或历史归档。上游版本改变时使用新的 `--data-dir`，不覆盖旧数据。
- 示例管理录音为 2 秒合成静音，四类偏误由人工构造。学生上传会执行真实保存和转码；未安装模型时诊断失败应单独核查，不能当作算法通过。
- 不要把这个开发模式启动器直接暴露为正式采集服务。

## 交互演示顺序

1. 进入管理工作区查看采集概览；切换等级，核对有效录音数与缺口。
2. 打开录音详情回放，查看已完成、等待、处理中、失败四种状态；保存备注，查看操作记录并撤销。
3. 新增或编辑测试题目/说话人；删除后选择“已删除”恢复。有关联或旧版本时页面应明确拒绝。
4. 导出 ZIP，使用后端 `verify_export.py /path/to/management-export.zip` 校验。
5. 命题工作区执行校验、统计、发布，查看真实报告并抽取已发布题目。发布失败需保留缺口，不能跳过门禁。
6. 学生注册、验证、登录、取题、录音或选择授权测试音频；试听后确认上传；“我的上传”查看服务器编号。刷新前后核对草稿与回执。
7. 右上角切换另一套风格，验证同样操作、同样数据。二者只改变视觉，不分叉业务实现。

## 正式服务接入与部署

统一 Web 由管理 FastAPI 提供，浏览器只访问一个 HTTPS 来源：

```text
浏览器（青绿 / 学院蓝）
  └─ HTTPS / Caddy
       └─ 管理 FastAPI：页面、管理 API、同源业务代理
            ├─ SQLite / 受保护音频 / 审计 / 导出
            ├─ /gateway/student → 学生服务（学生 session）
            └─ /gateway/proposition → 命题服务（管理授权后代理）
```

配置见 [部署环境清单](../backend/deploy/.env.example) 与 [部署和备份恢复](../backend/deploy/README.md)。管理服务设置 `STUDENT_BASE_URL`、`PROPOSITION_BASE_URL`；学生 `PUBLIC_BASE_URL` 与 `ADMIN_PUBLIC_ORIGIN` 都填写实际外部 HTTPS 来源。邮箱中的 `/static/auth.html#verify=...` 已接入统一入口。

管理和学生账号目前分别登录；正式统一身份方案未确认。代理仅转发白名单接口和必要 Cookie，管理令牌不会传给学生服务。上游服务应只在内网/本机监听，不直接公开未鉴权的命题写接口。正式模式设置 `ADMIN_COOKIE_SECURE=1`、学生 `APP_ENV=production` 与真实 SMTP；不设置 `PORTAL_DEMO`。当前管理会话为单进程内存会话，只使用一个 worker。

服务器、域名与证书确定后，必须补做真实 HTTPS、移动设备录音、网络中断恢复、跨组真实数据闭环验收。本机 HTTP 成功不是正式部署完成。

## 测试与维护入口

```bash
.venv/bin/python -m pytest -q '03_管理端/当前开发/backend/tests' '04_接口说明/联调工具/tests'
node --test '03_管理端/当前开发/web/test.mjs' '03_管理端/当前开发/web-components/test.mjs'
.venv/bin/python '03_管理端/当前开发/web/smoke_http.py' --base http://127.0.0.1:8891 --token-file '03_管理端/当前开发/local-data/portal-demo/access-token.txt' --output '03_管理端/当前开发/evidence/http-smoke.json'
```

HTTP 脚本拒绝非本机、非演示模式；会创建合成测试账号、上传静音，并在隔离题库内执行发布。测试来源与结果见[第三周交付记录](../../2026.11.23-2026.11.29第3周/三端Web交付与验证_20261125.md)。GitHub Actions 增加 Ubuntu、Windows、macOS 的后端/契约/JS 回归；浏览器、麦克风和真实算法测试仍需人工补齐。工作流使用 [官方 checkout](https://github.com/actions/checkout/releases/tag/v6.1.0) 与 [setup-python](https://github.com/actions/setup-python/releases/tag/v6.1.0) 的固定提交。

`app.mjs`：页面、交互和请求；`queue.mjs`：IndexedDB 草稿与上传回执；`pinyin.mjs`：展示用声调转换；`style.css`：青绿基准；`senior.css`：学院蓝顶部导航布局；`backend/portal.py`：同源代理与边界；`run_demo.py`：隔离运行器；`smoke_http.py`：真实 HTTP 回归。
