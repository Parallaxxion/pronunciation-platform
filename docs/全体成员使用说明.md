# 全体成员使用说明

本仓库采用一个Git仓库、三个普通业务目录。所有成员在同一份代码树中查看成果和协调任务；不需要理解Git子模块，也不需要先访问原仓库才能阅读学生端副本。

## 按身份找到位置

| 成员 | 主要目录 | 当前对接重点 |
|---|---|---|
| 学生组前端 | systems/student/frontend | 注册、题面、录音页面接入现有UI风格 |
| 学生组后端 | systems/student/backend | 命题接口、练习关联、授权管理查询与音频读取 |
| 学生组算法 | systems/student/backend/app/services | 输入规格、诊断状态、偏误索引与已知错读验证 |
| 命题组 | systems/proposition | 命题流水线、题库、发布抽题与采集覆盖同步 |
| 周佳怡 | systems/admin/prototype/static、shared/ui | 管理页面、核查、公共样式和偏误组件 |
| 闫晓奕 | systems/admin/prototype/server.py、integration、contracts | 核心管理、权限、撤销和跨组协调 |
| 王阳 | 管理端统计导出代码、samples、scripts | 计数、导出校验和部署说明 |
| 汇报与验收成员 | docs、evidence、各组reports | 检查进展、复现证据、整理问题 |

其他组个人负责人和公共前端维护人由三组补充确认。分工边界是协作约定，不是已经配置好的目录写入权限；总仓库写权限由维护者按实际成员另行安排。

## 第一次使用

```bash
git clone https://github.com/Parallaxxion/pronunciation-platform.git
cd pronunciation-platform
python -m unittest discover -s tests -v
python systems/admin/prototype/server.py --open-browser
```

Windows可用py -3，macOS/Linux可用python3。没有Git也可以下载整个ZIP查看、运行，但不能直接用git pull更新。只要公开总仓库可访问，就可取得所有三个目录。

源仓库README保留导入时的环境与运行说明。其中出现旧仓库克隆地址或旧协作方式时，获取和提交以本说明为准；各组命令在该组子目录执行。例如命题服务先进入systems/proposition，学生服务先进入systems/student，再按各自README建立环境。

## 日常开发

```bash
git switch main
git pull --ff-only
git switch -c feat/student-question-integration
# 在自己负责的目录修改；检查后明确选择文件
git add systems/student/backend/app/routes/questions.py
git commit -m "接入统一题目来源"
git push -u origin feat/student-question-integration
```

然后在本总仓库发起PR，写清验证结果和接口影响。有写权限的成员直接推自己的分支；没有写权限的成员可以fork本公开总仓库，再向总仓库提交PR。不在main上互相覆盖文件。

另一个成员检查后合并。开始新任务前先保存个人改动、回到main执行git pull。日常更新只用普通Git操作，不用submodule命令，不用手动更新某个子仓库指针。

## 与原仓库如何过渡

本次导入是来源版本清单对应的完整快照，未同步原仓库全部历史。建议三组确认后，第二周共同开发统一在本总仓库进行；原仓库作为既有历史保留。

若某组暂时仍在原仓库开发，该组每次交接提供明确commit和变更清单，由总仓库建立import分支后合入对应目录。先比较本总仓库是否也修改了相同文件，逐项解决冲突，完成测试后再合并，并更新source-snapshots.json与交接记录。不得用整目录覆盖来抹去总仓库的新改动。

不存在自动双向同步。三组需明确当前工作提交到哪里，避免在两个仓库同时修改同一功能。总仓库的集成成果和共同任务以本仓库为准。

## 验收与交接

每次交接写任务编号、实际负责人、PR或commit、运行命令、结果、阻塞项和约定下次检查时间。真实录音与私密配置保留在授权存储中，公共仓库使用合成或构造样例。
