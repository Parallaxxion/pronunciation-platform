二、需求与完成状态
1. 数据统计
任务书要求注册人数、各等级及各题收录量、缺口分布。
原型已展示匿名说话人数、有效录音数、题目覆盖、每题缺口和等级收录量。
统计口径为未删除录音计入有效量，同一学生同一题的不同录音序号分别计数。
覆盖题目指至少有一条有效录音的题。目标条数暂设3，缺口为max(目标-有效量,0)，尚需老师确认正式采集目标及是否按独立说话人数计量。

2. 数据核查
任务书要求按学生或题目查明细、回听、溯源和查看基线诊断。
原型已实现按题文、题号、录音号、说话人号搜索及按等级筛选，展示录音时间、序号和设备信息。可回听本地WAV。
四类标注覆盖声韵母误读、声调偏误、漏读、增读，增读锚定字间位置。
待接真实算法结果，确认多音字、轻声、变调、标点、首尾增读的共同约定。

3. 增删改查与撤销
任务书要求对用户、题目、录音等数据操作生效且可撤销。
原型当前实现用户和题目查询、录音备注编辑、软删除、恢复、操作日志和受版本校验保护的单次撤销。
原型会拒绝旧版本更新以及已有后续变更的历史撤销，避免覆盖他人修改。连续多步撤销尚需补充设计。
用户及题目新增、修改、删除，录音新增/导入及完整权限体系留到后续开发。
正式系统建议由数据所属服务处理写入和撤销，管理端经授权接口请求，避免多端直接修改同一数据造成规则分歧。

4. 数据导出
原型可生成ZIP，含WAV、original目录、manifest.jsonl、manifest.csv、annotations.jsonl、speakers.json、schema.json和说明。
每条录音都有独立导出路径，标注以recording_id关联。
演示原始文件本身就是WAV，因此original与audio中内容相同。真实接入时分别保留原始格式和标准WAV。
当前导出未删除记录。未来应支持包含已删除记录的授权归档，并明确题目快照与数据版本。
缺少文件时导出失败并报告错误，避免静默生成不完整包。

三、页面规划
采集概览，查看人数、量、覆盖和缺口。
录音核查，查询、详情、回听、偏误展示和备注。
题目覆盖，按等级和题目查看收录量。
说话人管理，匿名背景信息、相关录音、账号管理入口。
操作记录，查看变更、撤销和冲突提示。
数据导出，本期原型在各页放置统一导出入口。
正式系统补充管理身份登录与权限控制，真实邮箱只在必要的账号管理流程中按权限访问。

四、技术调研与路线初选
以下为基于官方文档的工程判断，团队尚未确认。

前端候选 Vue 3
支持声明式渲染、响应式数据和组件化，适合列表筛选、统计、详情弹窗和偏误标注组件。若团队已经掌握React，可沿用同等能力的栈，避免额外迁移学习。
https://vuejs.org/guide/introduction.html

后端候选 FastAPI
基于Python类型和数据校验，提供OpenAPI及交互式接口文档，有利于三端核对字段和请求格式。
https://fastapi.tiangolo.com/features/

数据库 原型采用SQLite
Python内置sqlite3可使用本地数据库，无独立数据库服务，适合验证持久化、关联和事务。正式部署应根据团队已有数据库、并发与备份要求共同选择，暂以PostgreSQL作为候选，迁移与并发性能均未验证。
https://docs.python.org/3/library/sqlite3.html

录音回听采用浏览器audio元素
可提供播放、暂停、进度与音量控制。正式接入需核对音频授权、MIME、Range请求、不同浏览器兼容性与过期URL行为。
https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/audio

本次可运行原型的实际栈
原生HTML/CSS/JavaScript + Python标准库HTTP服务 + SQLite + 本地WAV文件。
此选择便于今晚直接启动并验证交互，原型不依赖网络CDN。后续按团队决定迁移到Vue/FastAPI，复用字段与业务流程。
本地标准库HTTP服务仅用于演示。正式服务需身份认证、授权、HTTPS、输入校验和部署配置。

五、系统对接方式草案
命题端拥有题目及版本，提供文本、字与拼音序列、等级和语法标注。
学生端拥有匿名背景信息、录音元数据、文件与基线诊断结果。
管理端调用上游查询和写入接口，保存管理操作、导出任务和审计记录。
组内确认是否采用统一后端或分服务。接口协议独立于语言，其他子系统无需使用同一种框架。
本地原型使用独立演示数据库。生产系统数据所有权和同步策略尚待对接。
